## CSVの実際の壊れ方

- Excelで開いて保存されると、日付がシリアル値に化け、電話番号の先頭ゼロが落ちる
- 同じ列名が2回出るCSVがある（`ConvertFrom-Csv` は丸ごと失敗する。自前で読む）
- **旧々logoフォームは全体が1つ右へずれている**（読むときに直している）
- ヘッダー行数がソースによって違う（LoGoは2行、関係者システムは1行）
- 文字コードは Shift-JIS(cp932) と UTF-8 が混在。BOMの有無で判定して読み分ける

## 人物ID

`S-00001` の形。**ソースが持っている番号をそのまま使い、機械は新しい番号を作らない。**
例外は2つ。

- 画面から新しく登録した人 … `S-90000` から機械が振って書き戻す
- イベントの申込にだけ出てくる人（2026-09-24）… 同じ 9xxxx の枠から機械が振る。条件は、氏名があり、
  電話・メール・LINEユーザーIDのどれかがあり、そのどれも名簿のだれにも一致しないこと。
  採番台帳では、**その人が初めて出てきた申込の行だけ**が採番（9xxxx）を持ち、状態は `イベントから載せた`。
  次の実行では、2巡目の前にその行から人を名簿へ戻してから結び付けるので、読む順が変わっても番号は変わらない。
  ほかの行がこの人に結び付いても、採番の欄は空にする（台帳の一意性の検査は 9xxxx が2行に付くと止まる）。
  非会員、関係者区分「イベントのみ」、便りは送らない（発送不要）
- 統合 … 人が採番台帳の人物ID列を書き換えて寄せる。**機械は候補を出すだけ**

採番台帳の採番の欄は、**列があって空のときは空のまま読む**（2026-09-24）。人物IDで埋めるのは、
採番の列そのものが無い古い台帳だけ。

## 住所と所属の決め方（2026-09-09 追加、2026-09-11 採用）

`Set-JushoAn` が住所の4項目を、`Set-Shozoku` が所属の4項目を、それぞれ1組にして
**行の日付が新しいほうから丸ごと採る。**同じ日付なら、あとから読んだソースが勝つ。
日付が読めない行は、まだ何も入っていないときだけ採る。
関係者システムの住所が都道府県で始まるときは、切り出して都道府県の列に入れる。
手で入れたことは1項目ずつ当たり、日時が最終更新日以降なら勝つ（ここは変えていない）。

## 状態の定義

| 項目 | とりうる値 | 意味 |
|---|---|---|
| `いいねぇ隊会員状態` | `会員` / `非会員` / `退会` | **機械が付けるのは会員と非会員だけ。**退会は人が画面から |
| `加入歴` | `有り` / `無し` | 一度でも入会フォームを通ったか。退会しても `有り` のまま |
| `レコード状態` | `有効` / `消去済` | 削除請求で消した人。消去済は氏名などを空にする |
| `便りの区分` | `郵送` / `メール` / `LINE` / `持参` / `一時停止` / `送らない` | 元の値を許可表で寄せたもの |
| `関係者区分` | 省庁 / 県 / 市町 / 企業 / 団体 / 報道 / その他 | 画面から登録するときに選ぶ |

**知らない値は黙って通さない。**許可した値以外は「要確認」に出す。

## 2つの軸（足してはいけない）

数え方が2つあり、**混ぜると答弁で崩れる。**

```
加入歴でみる … 累計の加入者    のうち  いまも会員 ／ 退会・除隊
名簿でみる  … 関係者（名簿の全員） のうち  会員 ／ 会員以外
```

この2つを足し合わせない。名簿に載っている人は全員が関係者で、**その中で
いいねぇ。隊に入った人が会員に上がる、という入れ子**である。

## 人が書くCSV 1. 手で入れたこと.csv

**すべて `03_判断を書き込む` に置く。**

**1行1項目、追記のみ。**画面から入れた値はここにしか無く、**取り直せない。**
行が減っていると実行が止まる。

列 … `日時, 入力者, 種類, 人物ID, 受付番号, 項目, 値, 理由`

`日時` は画面が秒まで入れる（`2026/09/11 14:20:05`。2026-09-11 から）。取り込みは
日時・種類・人物ID・項目が同じ行を「もう入っている行」とみなすので、日付だけだと
同じ日に同じ欄を2回直したときに2回目が捨てられる。

`項目` に書ける値（`$TeProps` が正）。

```
姓 / 名 / 姓カナ / 名カナ / 法人名 / 部局 / 課 / 役職
郵便番号 / 都道府県 / 住所 / 方書 / 電話 / メール
会員状態 / 便りの届け方 / 業種 / 関係者区分 / 備考 / レコード状態
```

**画面から会員は作れない。**会員状態で選べるのは、いま会員の人だけが
`会員/非会員/退会`、そうでない人は `非会員/退会` のみ。

## 人が書くCSV 2. 追記型のファイル（画面が保存のたびに新しく作る）

`file://` から既存ファイルへ追記はできないので、**保存のたびに新しい1本を書く。**
これで2人が同時に保存しても、どちらかが消えることがない。

| 名前 | 中身 |
|---|---|
| `手で入れたこと_追加_日時_職員番号.csv` | 新しい人を足す、この人を直す、要確認の便りの届け方。日時は秒まで（1分に2回保存しても上書きしない） |
| `統合判断_追加_日時_職員番号.csv` | 同一人物／別人／保留 |
| `出席_日時_職員番号.csv` | イベントの出席。列は `人物ID, 氏名, 行事, 日付, 入力者` |

取り込みが済んだものは `03_判断を書き込む\取込済\yymmdd\` へ移す。**消さない。**

**出席は `出席の記録.csv` に積み上げる**（2026-09-24）。取り込みは `出席_*.csv` の行を本体の末尾に足してから
ファイルを移し、毎回その本体を読んで出席回数を数える。人物ID・行事・日付が同じ行は1回に数える。
それまでは本体が無く、`取込済` へ移したあとは読まなかったので、**出席は記録した直後の1回の取り込みでしか
名簿に入らず、次の取り込みで消えていた**（2026-09-08 から）。本体は手で入れたこと.csv と同じく
取り直せない。行が減っていると実行が止まる。実行前の確認と控えにも入れてある。

## 受付番号

`関係者-20260908-481637-01` の形。**日付＋職員番号＋その日その人の連番。**
職員番号を入れるのは、2人が同時に登録したときに番号が衝突して
**片方の氏名が黙って消える**のを防ぐため。

**連番は取り込み済みの続きから採る**（2026-09-11）。build が `手で入れたこと.csv` から
「関係者-日付-職員番号-」ごとの最大を数えて画面に焼き込み（`meta.teNo`）、画面は保存先フォルダの
追加ファイルと本体も読んで足す。以前は追加ファイルだけを見ていたので、同じ日に取り込みを回すと
（追加ファイルは `取込済` へ移る）次の登録が -01 に戻り、取り込み済みの別人と同じ番号になっていた。

## HTMLにJSONを埋めるときの注意

`ConvertTo-Json` は `< > & '` をわざと逃がしている。**読める形に戻す処理で、この4つを
戻してはいけない。**戻すと、データに `</script>` が入った瞬間に画面が真っ白になる。
エラーも出ない。

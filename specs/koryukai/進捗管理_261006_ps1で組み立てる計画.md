# 交流会進捗管理を ps1 で組み立て直す計画（2026-10-06）

ユーザーの提案（2026-10-06）。中身は庁内で使っている `★交流会進捗管理★.xlsm`（9/29保存、`20_plans/` に置いたもの）を正とする。
ブックは ps1 で組み立て、マクロは `.bas` で入れる。令和8年度交流会の照合用Excel（2026-09-29 に庁内で通った）と同じ持ち込み方にする。

## いまの姿

- 庁内のブックには**マクロが入っていない**。ボタンが2つ残っているが、押しても動かない
- 「進捗入力」と「【印刷用】全体スケジュール」が改ページプレビューのまま保存され、既定プリンターが応答しない端末では開かない
- 私用PCの `30_deliverables/●交流会進捗管理.xlsm`（マクロ入り）は、庁内とは別物になっている。`.xlsm` は無害化を通らないので、そのまま持ち込めない
- `tools/build/` の ps1（01〜18）は7〜8月に私用PCで作ったもので、私用PCのパスが書き込まれ、庁内では動かない

## 提案する姿

持ち込むのは zip 1つ（中は英数字の名前の `.bat`、`.ps1`、`.bas`、`.cls`。どれも `.txt` を付けて運ぶ）。

**押す場所。**庁内で、いまの `★交流会進捗管理★.xlsm` と同じフォルダに展開し、`.txt` を外して `build_progress.bat` をダブルクリックする。

**押した直後。**ps1 が Excel を裏で開き、次の順に進める。対話は求めず、結果は `作成結果.txt` に書く。

1. 新しいブックを作る。シート4枚（使い方、進捗入力、【印刷用】全体スケジュール、設定テーブル）、表3つ（ProgressTable、CategoryMaster、StatusMaster）、入力規則、書式、ボタン、印刷範囲を、いまの★と同じ形で作る
2. 同じフォルダのいまの★を**読み取り専用で**開き、表の中身（進捗の行、設定テーブル）を新しいブックへ写す。★は書き換えない
3. 全シートを標準表示にして `交流会進捗管理.xlsm` の名前で保存する（★と並べて置く。★は消さない）
4. マクロは `VBProject.Import` で入れてみる（庁内の AccessVBOM の値は分からないので、通らなくてもよい）。通らなかったら、`作成結果.txt` に手で入れる手順を書く。Alt+F11 → ファイル → ファイルのインポートで `.bas` を選ぶ（9/29 に庁内で通った経路）

**次に開いたとき。**新しいブックを開くと、マクロが入っていれば次のことが起きる。

- 業務の絞り込み（B3）、サマリー、状態の色付けが動く。ボタンも動く
- 保存する直前に、全シートを標準表示へ戻す（改ページプレビューのまま保存されて、開かない端末が出るのを防ぐ）

## 作りで気をつけること

  - 生成元は私用PCの python（照合用の `build_ps1.py` に当たるもの）。そこから庁内用の `.ps1` と `.bat` を `package_src` に書き出し、`make-package.ps1` で zip にする
  - 庁内では 展開 → `K:\_無害化復元\restore.bat` で `.txt` を外す → bat をダブルクリック
  - マクロの入れ方は3つ用意する（自動の `VBProject.Import`、ファイルのインポート、貼り付け用のテキスト）。どれか1つ通れば動く。ボタンはマクロが入ったかに関係なく ps1 が必ず置く
  - 日本語の名前のもの（できるブック、`作成結果.txt`、貼り付け用のテキスト）は PowerShell 側で作る。zip の中は英数字だけ
  - A4 1枚の手順書を付ける
- **シートとブックのイベントは `.bas` では入らない。**いまの作りは `ThisWorkbook`（開いたとき）と `Sheet1`（B3を変えたとき）にマクロを書いているが、これはファイルのインポートでは入れられない（`.cls` を入れると、別のクラスができるだけで動かない）。代わりに、標準モジュールの `Auto_Open`（開いたときに動く）と、クラスモジュール1つで Excel のイベントを受ける形にする。クラスモジュールはインポートで入る
- 開くときの処理は軽くする（今日 `●` に入れた直しと同じ。書式の設定は組み立てのときに1回だけ行い、開くたびには行わない）
- 写すときに、いまの★の列の並びが想定と違ったら、止めて `作成結果.txt` に違いを書く（黙って写さない）
- 持ち込み物は `~/.claude/tools/make-package.ps1` を通す

## UI/UXの見直し（2026-10-06 調べ、ユーザー確認待ち）

庁内の★（9/29保存）を私用PCで開いて、画面を画像にして見た。見つけたことと、直す案。

**いまの画面で気になったこと**

- 進捗入力の上の固定部分（1〜11行目：業務選択、担当、現状、今後、打合せ事項）が大きく、ノートPCの画面では表が数行しか見えない
- 時期を過ぎて終わっていないタスクが目立たない。例えば「派遣生に事前告知」（8月上旬）が未着手のまま、ほかの行と同じ見た目
- 「今後」に、もう過ぎた8月中旬の項目が並ぶ（遅れと予定が混ざる）
- 報告事項・メモに「【（氏名）入力】」のように手で名前を書いている。いつ書いたかが分からない
- 絞り込みは業務だけ。自分の担当分だけを見ることができない
- 「タスクを追加」のボタンが5つ重なって置かれ、どれも動かない。「進捗更新」も動かない（マクロが無いため）
- 業務選択の横の案内が「タブで選択」になっているが、実際はプルダウン
- 印刷用：■▲□の意味（完了、進行中、未着手）の凡例が無い。開催日の行が「21日」のまま（令和9年1月13日の会と合わない）
- 上の要約（担当、現状、今後、打合せ事項）と印刷用は、マクロが書いた文字が残っているだけで、いまは更新されない

**入れる改善（2026-10-06 ユーザーが選んだ）**

- 遅れを色で示す（今日の旬を過ぎて完了でない行に色。「今後」を遅れ／これからに分ける）
- 上の固定部分を小さくする（担当と現状を1行に。今後・打合せ事項は表を狭めない場所へ）
- 担当者でも絞り込む（業務の横に担当者のプルダウン）
- 前提として入れる：ボタンは「タスクを追加」「印刷用を更新」の2つに整理、案内の文言を直す、印刷用に■▲□の凡例、開催日は設定テーブルから

入れない：更新日の自動入力（選ばれなかった）

**タスクの追加はポップアップ（入力フォーム）にする（2026-10-06 ユーザー提案）**

- 「タスクを追加」を押すと小さな窓が出て、業務、月、時期、タスク、メイン担当、サブ担当、進捗状況、報告事項を選ぶか書く。「追加」で表の最下段に1行入り、並べ替えまで済ませる
- 業務を選ぶと、設定テーブルの既定担当がメイン担当、サブ担当に入る（変えられる）
- 作り方：フォームは `.frm`（文字）と `.frx`（中身の入れ物。バイナリ）の2本組でないと入らない。2026-10-06 に私用PCで確かめた（`.frm` だけでは「エラーを特定できません」で入らない）。
  `.frx` はバイナリで無害化を通るか分からないので、**ps1 の中に base64 の文字で埋め込み、庁内で ps1 が `.frx` を書き戻す**。部品（プルダウン、入力欄、ボタン）は `.frx` に持たせず、フォームが開くときにコードで並べる。
  私用PCで、base64 から書き戻した `.frx` で入り、部品が並び、保存して開き直しても動くことを確かめた（2026-10-06）
- **庁内でフォームが入るかは未検証。**入らなくても他のマクロが止まらないように、フォームは名前で呼ぶ（`VBA.UserForms.Add("frmAddTask")`）。呼べなかったら、いまと同じく表の最下段に空の行を足す

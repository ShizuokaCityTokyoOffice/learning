設計の正は `../../20_plans/260916_業務フロー設計書_招待から受付まで.md`、タスクの正は `../../タスク.md`。

マクロ入りの `.xlsm` はファイル無害化で持ち込めないので、テキストで持ち込んで庁内で組み立てる。

bat を1回押すと、同じ場所に `R8申込突き合わせ.xlsm`、`突き合わせ.bas`、`マクロ_貼り付け用.txt`、`作成結果.txt` の4つができる。

**マクロの入れ方は3つあり、どれか1つ通れば動く。**

| 順 | 入れ方 | 要る設定 |
|---|---|---|
| 1 | スクリプトが `VBProject.Import` で入れる（自動） | `AccessVBOM=1` |
| 2 | Alt＋F11 → ファイル → ファイルのインポート で `突き合わせ.bas` を選ぶ | 要らない |
| 3 | 挿入 → 標準モジュール に `マクロ_貼り付け用.txt` を貼る | 要らない |

1が通らなくても `作成結果.txt` に2の手順が出る。庁内の `AccessVBOM` は6月の生ログが
ちょうどその値のところで切れていて確かめられないので、**2を本線と考える**
（ユーザーが過去に別の案件で `.bas.txt` を持ち込んで `.txt` を外し、インポートで通した経路）。
**3つとも私用PCで、マクロが入って `突き合わせる` が走るところまで確かめてある。**

**ボタンは、マクロが入ったかどうかに関係なく、スクリプトが必ず置く**（2026-10-02）。
「使い方」に7つ（ファイルを取り込む×2、①〜⑤）、結果の8枚と取り込み先の4枚の左上に「← 使い方へ」、「取り込んだファイル」の4つの欄に、押すとそのシートを開く透明の図形。
以前は `VBProject.Import` が通ったときだけ置いていたので、経路2・3では手で図形を作ってマクロを登録していた。
ボタンの `OnAction` は名前の文字列を持つだけなので、あとから手でインポート・貼り付けしたマクロに自動でつながる。
`Import` を失敗させた版にあとから `.bas` を入れ、5つとも対応するマクロの開始行に行き着くことを私用PCで確かめた。

`マクロ_貼り付け用.txt` には `Attribute VB_Name` の行を入れない。入っているとVBEが受け付けず、
貼ったあとマクロが1つも見えなくなる（2026-09-28に実際に再現した）。`.bas` の方は逆に、その行が要る。

**ENVIRONMENT_SPEC の作法に合わせてある。**

- 持ち込み物は必ず `~/.claude/tools/make-package.ps1` を通す（実値の検査つき。2026-09-28 は0件で通過）
- zip の中のファイル名は英数字だけ。bat から呼ぶ `.ps1` も英数字
- 庁内では 展開 → `K:\_無害化復元\restore.bat` で `.txt` を外す → `run_matching_tool.bat` をダブルクリック
- 対話を求めない（`pause` も入れない）。画面が閉じても分かるよう、結果を `作成結果.txt` に書き出す
- 日本語の名前のもの（できるブック、`マクロ_貼り付け用.txt`、`作成結果.txt`）は PowerShell 側で作る

  -Source 30_deliverables\package_src -Name R8matching -OutDir 30_deliverables\_package

**画面（シート、ボタン、使い方の文、操作盤）を直すのは `build_ps1.py` だけ。**
以前は見本を `build_book.py` と `make_xlsm.ps1` で別に作っていて、ボタンの数や使い方の文が庁内の版と食い違っていた。この2本は2026-10-07に消した（ユーザー判断）。

マクロ本体は `tools/突き合わせ.bas`（UTF-8。これは**生成元**）。**VBEが読むのは `突き合わせ_cp932.bas` の方。**
`build_ps1.py` が cp932 版も一緒に作るので、手で変換する手順は無い（忘れて古いものを取り込む事故を防ぐため）。
cp932 にできない文字を書くと `build_ps1.py` がそこで止まる。

**宛名ラベルの画面は `tools/label_page_template.html`（ひな形）に書いてある**（2026-10-13）。上の帯、4つの段、一覧、調整の窓、JavaScript。
`build_ps1.py` がこれを VBA の関数 `LabelTemplate` に直し、`突き合わせ.bas` の印 `'@@LABEL_TEMPLATE@@` の所へ差し込む（60行ごとに関数を分け、長い行は300字で切る）。
だから `突き合わせ.bas` は、そのままでは VBE に入れられない。入れるのは `build_ps1.py` が作った `突き合わせ_cp932.bas` の方。
ひな形の中の `@@N@@`、`@@DYNCSS@@`、`@@CONFIG@@`、`@@BODY@@` は、マクロの `LabelPageHtml` が、人数、台紙とラベルの寸法のCSS、画面に渡す値、ラベルの中身に置き換える。
ひな形に全角の数字や波線そのものを書かない（正規表現の中は `\uFF10` の形で書く。庁内で化ける字は `build_ps1.py` が止める）。

## 決まっていること

**画面（2026-10-02 ユーザー判断。計画は `20_plans/261002_UIUX改善_計画.md`）**

- **ボタンの番号は押す順。**案内状を送る前が ① 宛名ラベルを作る ② LINEの宛先を確かめる、申込が来たら ③ 突き合わせる ④ 2人目以降のURLを作る、締め切ったら ⑤ 名簿を作る。マクロの名前は変えていない（旧 ①→③、②→⑤、③→④、④→①、⑤→②）
- 「使い方」の上を操作盤にした。左にボタンを時期ごとに縦に並べ、右に「いまの状態」（申込人数、230・250の目安、要確認と〇×がまだの件数、最後に突き合わせた日時）と「取り込んだファイル」。**13.3型FHDを150%で使った場合（実効1280×720）に全部見える大きさ**にして、私用PCで1280×672の窓で撮って確かめた
- **ファイルを取り込む。**CSVやExcelを選ぶと、1行目の見出し（LoGoは2行目の設問の文も）で入れるシートを決める。何を探すかは「設定」から読む。CSVはBOMがあればUTF-8、無ければcp932。CSVは文字列のまま入れる。入れる前にシートを空にする（LoGoのCSVは毎回全件のため）。Excelは全シートを見て当てはまるシートを使う。どれにも当たらないファイル、同じシートに2つ目のファイルは入れずに知らせる。実物のLoGoのCSV2本、R7のマスター案内状送付者リスト（シート2枚）、無関係なCSV、囲みと改行入りのCSVで確かめた
- **LoGoの書き出し（1行目に「回答番号」「回答日時」がある）で、設問の見出しが「設定」と合わないときは、どちらのフォームかを人に聞いて入れる。**
  2026-10-02 夕、庁内でLoGoのCSVが「どのシートに入れるか分かりませんでした」になった（リストは入った）。原因は未特定で、設問番号の変更か書き出し形式の違いと見ている。
  あわせて UTF-16（BOM FF FE）とタブ区切りも読むようにし、決められないときはメッセージに1行目の見出しを出すようにした。
  設問番号を変えた版、UTF-16タブ区切り、UTF-8 BOM、Excel版、無関係なCSVの5つで確かめた
- **シート「設定」を作り直した**（2026-10-02 夜。2回）。
  1回目は「造りが悪い。これじゃ誰も修正できない」という指摘で、表3つを横に並べ `38:number` を手で打たせる形をやめ、縦1本にしてプルダウンで設問を選ぶ形にした。
  2回目は庁内で試して「プルダウンで選ぶのが実際の業務と合っていない」という指摘で、**見本の見出しから自動で作り、当たらない欄だけ列の文字を打つ**形にした。いまの形は次のとおり。
  - 縦1本。節は 1 受付の人数と、そのほかの値（値はD列）/ 2 申込フォームの欄 / 3 2人目以降フォームの欄 / 4 案内状発送対象者リストの列。節ごとに「いつ触るか」を書いた
  - フォームとリストの欄は、**C列に列の文字（J など）**。D列に、その列の設問が式で出る（隠しシート「見本の見出し」から引く）。E列が状態（〇か×）
  - **LoGoの書き出しの1行目は「設問ID:設問の種類」、2行目は設問の文。**取り込んだとき、「見本のファイルから作る」とき、③を押したときに、欄の列を次の順で当て直す（`RebuildSection`）
    1. 前の見本で、その列にあった設問IDの設問を探す（同じ設問IDでも文が違えば別の設問とみなす）
    2. 同じ設問の文で、同じ種類の列を探す（設問を作り直して設問IDが変わったとき）
    3. 設問の種類と、設問の文の言葉の決まりで探す（`RuleFind`）。お名前の姓（lastname）が出るたびに次の人の欄が始まる。申込フォームは文に「同伴」の無い人がご本人、ある人が同伴者。1人分の中は、勤務先・役職（文字で、その言葉）、領収書は同じでよいか（選択で「領収書」）、領収書の宛名（文字で「宛名」）。管理番号は数字の種類。LINEユーザーIDは、文が空で1列だけの文字の設問が1つだけのとき。2人目以降フォームはお名前が出た順に2人目〜6人目。リストは見出しの言葉そのもの
    4. どれでも当たらない欄は、C列を空にして × にし、前に当たっていた設問をD列に出す。人が列の文字を打つ
  - **新しいフォームを作ったときは「見本のファイルから作る」**（節2〜4の見出しの右）。試しに1回答えて書き出したファイルを選ぶ（ユーザーに確かめた実際のやり方）。申込データには入れず、「設定」だけを作る
  - ③は、まず `SyncSettings` で当て直し、×が残っていれば進まずに「設定」を開く（手で貼り付けたときもここで合う）
  - 決まりは、このPCにあるLoGoの書き出し16種類（261ファイル）を調べて決めた。左の9列はどれも同じ（回答番号…利用者番号）。何列かに分かれる設問は同じ設問IDが続き、文は先頭の列だけ。隠した設問は文が空。設問IDは作った順に付き、並び順とは関係ない（16種類中14種類で並び順と違う）
  - 確かめたこと：
    - 去年の交流会申込（R7）から作る → 19欄が当たり、LINEユーザーIDだけ ×（去年はLINEの設問が無かったので正しい）
    - 今年の申込フォーム、2人目以降フォームから作る → 全部当たる
    - 設問IDを全部ずらし、ご本人の「勤務先」を「ご所属」に変えたファイルを取り込む → 勤務先だけ ×、R を打つと 〇、③が通る
    - 交流会でない13種類（いいねぇ隊の入会、イベント、アンケート）→ 勤務先などに取り違えて当たることは無かった（当たるのはお名前、回答日時、隠した設問だけ）。管理番号の設問が無いので、取り込みでは申込フォームとみなされない
    - 通し試験の結果は作り直す前と同じ
- **照合結果の最終行は「本人・同伴者」の列（B列）で見る。**以前はA列（管理番号）で見ていて、いちばん下がリストに当たらなかったLINEの方（管理番号が空）だと、要確認にも名簿にも出なかった。2026-10-02、試しの回答1件（LINEから、リストに無い）で要確認が0件になって見つけた。直したあと1件になることを確かめた
- **マクロに「〜」（U+301C）を書かない。**庁内でマクロを書き出す PowerShell（.NET）の cp932 では「?」になる。名簿の知らせが「名簿No. 1 ? 254」になっていた（2026-10-02 庁内で見つかった。私用PCの試験結果にも出ていたのに見落としていた）。「名簿No. 1 から 254 まで」に直し、注釈の〜は～にそろえた。Python の cp932 は〜を通してしまうので、`build_ps1.py` は往復して同じ字に戻るかで検査し、化ける字があれば作る前に止める
- **マクロの宣言（Const、モジュールの変数）は先頭に置く。**作り直しの途中で手続きの間に置いてしまい、コンパイルが通らず、見えない所でエラーの窓が出て固まった。`build_ps1.py` が作る前に検査して止めるようにした

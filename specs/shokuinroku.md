# 職員録ビューア 要件定義書

最終更新 2026-09-01
現行版 `再構築2_組織図版`（組織機構図で局・部・課を決める版）

## 1. 何のために作るか

静岡市役所の職員録は Excel で配られている。局・区ごとに26枚のシートに分かれ、1枚あたり31列、
全体で約4,900名。この形だと、部署をまたいで人を探せない。「総務課の課長は誰か」「この内線は誰か」
を調べるのに、どのシートを開けばよいかから考えることになる。「見づらい、探しづらい」が主訴。

そこで、同じ Excel をそのまま入力にして、検索と絞り込みができる1枚の HTML を作る。
年1回の人事異動のあとに作り直す。データを直すのは Excel の側で、ビューアは閲覧に徹する。

## 2. 使う人

閲覧するのは全職員（約4,900名）。作り直すのは人事担当の1〜数名。

利用者像は「連絡のために内線を引く一般職員」の1つに絞ってある。庶務担当、新任、役職者といった
細かい区分は、実際の使われ方を見るかぎり分ける意味がなかった。詳しい根拠は `UX設計.md`。

## 3. 開発用データとセキュリティ

**この節がこの案件でいちばん大事な前提。**

**開発にはダミーデータを使う。**

このプロジェクトの開発用データ `001_R08_shokuinroku.xlsx` はダミーで、実在する職員は
1件も入っていない。

| 列 | 見出し | 状態 |
|---|---|---|
| Z | 氏名 | ダミー（4,911件） |
| AA | フリガナ | ダミー（4,911件） |
| AE | 備考 | ダミー（101件。残りは空欄） |
| 上記以外の28列 | 所属名称、係情報、職名、職種、兼務、内線、外線、FAX ほか | 本番と同じ構造 |

氏名を伏せた時点で、残る28列は組織の情報と代表番号であって、特定の個人を指さない。
そこに架空の氏名を入れて、件数と形だけを本番にそろえてある。

**なぜダミーでやるのか。**

**開発しているのはインターネットにつながる私用PCだから。** 静岡市の三層分離は、個人情報を扱う
系をインターネット系から切り離すためにある。開発だからという理由でその線をまたげば、
仕組みそのものを迂回することになる。だから開発側には個人情報を持ち込まない。
「持ち込まないよう気をつける」ではなく「持ち込みようがない状態にする」で守る。

もう一つ、開発の実務上の理由がある。画面を直す作業では、ファイルを生成AIに読ませ、出力を貼り、
ログを共有する。そのどれもが外部へ出ていく経路になり得る。中身がダミーであれば、経路を1本ずつ
塞ぐ検討をしなくてよい。

そして、開発に必要なのは4,911件という量と31列という構造であって、実在の氏名ではない。
画面が崩れないか、40秒弱で終わるか、検索が速いかは、氏名が架空でも同じように試せる。

**ダミーの作り方。**

本番と形を合わせてある。形が違うと、試しても意味がなくなるため。

- 氏名は `大塚　豊` のように姓と名を全角スペースで区切る
- フリガナは `オオツカ　ユタカ` のカタカナ。拗音と促音は大書きにする
  （庁内システムの癖に合わせている。`ジユンヤ` `シユンスケ` と入る。かな検索の挙動を
  本番と同じにするため、ここを再現している）
- 姓150種と名110種の組み合わせから、乱数の種を固定して振っている。同じ結果を再現できる
- 備考は101件（約2.3%）。本番の出現率に合わせた。派遣先などの固有名詞には「ダミー」を
  混ぜてあり、実在の団体名にはしていない
- 件数は4,911件、シート構成は26枚、列は31列で本番と同じ

**ダミーで確かめられること、確かめられないこと。**

**通ったことと、動くことは違う。** ダミーで試せる範囲を、はっきり分けておく。

確かめられる。

- 画面のレイアウト、列幅、1画面に何行入るか
- 4,911件での検索とソートの速さ
- 生成時間（Excel COM 経由で37秒）、EXCEL.EXE が残らないこと
- 組織機構表との突合率、どの所属が表に無いか
- 出力サイズ、文字化けの有無、無害化ゲートウェイを通るかどうか
- 兼務の配列化、所属名称の切れ目、チップの OR と AND の挙動

確かめられない。ここは**庁内で本番の職員録に対して初めて動かすときに見る**。

- 外字と異体字。実在の氏名には `﨑` `髙` `栁` のような、ダミーの姓名リストには出てこない
  字が入る。表示、検索、フォントの当たり方はそこでしか試せない
- 備考の自由記述に入る想定外の文字列。`</script>` のような文字が入ると名簿が真っ白になる。
  update.ps1 側で `<` `>` `&` `'` を `\uXXXX` に逃がして塞いであるが、本番で確かめる
- 実際の同姓同名の見え方、氏名の長短による列幅の破綻
- 氏名を含めたときの検索の当たり方、フリガナの表記ゆれ

**職場PCで使うときに守ること。**

- 庁内の職員録 xlsx と、そこから生成した `職員録.html` は**庁内から出さない**。私用PCへ
  持ち出さない、メールに添付しない、USBに入れない、生成AIに読ませない
- 私用PCから庁内へ渡すのは `update.bat`、`update.ps1`、`orgtable.csv` の3つだけ。
  **xlsx は転送しない**。庁内側にある職員録をそのまま使う。名簿は行き来させない
- 持ち込む3つはいずれも中身が読めるプレーンテキスト。難読化や圧縮で隠していないので、
  情報管理担当の確認を受けられる状態にしてある
- 無害化ゲートウェイは迂回しない。HTML を送らず庁内で組み立てる設計は、無害化の仕様
  （`<script>` を削除する）に合わせたものであって、すり抜けるための細工ではない
- 庁内で生成した `職員録.html` は、全職員の氏名と連絡先が入った個人情報ファイルとして扱う。
  職員が見られる共有フォルダに限って置き、外部公開領域には置かない
- 年次更新で作り直したら、**古い `職員録.html` は残さず消す**。異動前の情報がいつまでも
  引ける状態にしない
- 庁内で生成したものを庁内の外へ写さない。生成物は作った場所の外へ散りやすいので、
  作業が終わったらその場で片付ける

## 4. できること

| ID | 機能 | 中身 |
|---|---|---|
| F-1 | 横断検索 | 氏名、フリガナ、所属、職名、職種、内線、外線、FAX、備考、兼務先をまとめて対象にする。スペース区切りで「かつ」 |
| F-2 | かな正規化 | 「やまだ」と打つと「ヤマダ」も「山田」も当たる。全角スペースと大小文字も吸収する |
| F-3 | 課で探す | ヘッダのボタンから、全課を一覧して直接選ぶ。局を覚えていなくても辿れる |
| F-4 | 局チップ | 26局・区で絞る。同じ帯の中は「どれか」（OR）なので、2つ選んで0名にはならない |
| F-5 | 課チップ | 局を選ぶと、その局の課チップが出る。局を外すと課も連動して外れる |
| F-6 | 列の値で絞る | 列見出しから、その列に出ている値を選んで絞る。帯の中は OR、帯どうしは AND |
| F-7 | 表示する列 | 14列から出す列を選ぶ。選んだ内容は localStorage に残り、次に開いても続く |
| F-8 | 兼務 | 兼務は最大3件を配列にする。兼務先からも検索で当たる。「兼務ありだけ」で絞れる |
| F-9 | 詳細パネル | 行を押すと右からスライドして1件の全項目を出す |
| F-10 | ソート | 見出しを押すと昇順と降順が切り替わる。既定は Excel の行順（＝組織順） |
| F-11 | キーボード | `/` で検索欄、`↑` `↓` で行移動、`Esc` で閉じる |
| F-12 | 件数と鮮度 | 「4911名中 N名」と、作り直した日時を画面上部に出す |

出せる列は14。既定で出るのは氏名、局・区、部、課・室、係、職名、内線、外線の8列。
既定で隠しているのはフリガナ、所属（元の表記）、職種、FAX、兼務先、備考の6列。
列の幅は選ばれた列の重みで100%に配り直すので、何本選んでも横スクロールは出ない。

## 5. やらないこと

意図して外している。

- データの編集。管理者が Excel を直す運用
- ローマ字検索。`yamada` で `山田` を引く。工数に見合わない
- 課名のかな検索。課名にフリガナが無いので「そうむ」では当たらない。当てるには課名の読みの表を
  持つしかない。いまは「課で探す」の例示を漢字にして逃げている
- 係（第3階層）のチップ。列の絞り込みで代替できている
- 印刷用のスタイル。Excel から印刷する想定
- スマホ表示。PC でしか使わない
- ダークモード

## 7. データ

**入力。**

ファイル名は `001_R08_shokuinroku.xlsx`。26シート、各31列、1行目が見出し。
列は位置ではなく**見出しの名前**で探しているので、列が増えても順序が変わっても動く。
逆に、見出しの文字が変わると止まる。そのときは「氏名という見出しが見つからない」と出る。

| 列 | 見出し | 使い方 |
|---|---|---|
| A、C | PHP部課CD、係ＣＤ | 使わない |
| B | 所属名称 | 局・部・課の切り出し元。「所属（元の表記）」列にも出す |
| D | 係情報 | 係 |
| E | 職名 | 職名 |
| F、G | 職名CD、職名名称 | 使わない |
| H、I | 職種CD、職種 | 職種 |
| J〜X | 兼務1〜3（5列×3組） | 配列にする |
| Y | 管理番号 | 使わない |
| Z | 氏名 | 一覧、詳細、検索 |
| AA | フリガナ | 検索 |
| AB | 内線 | 一覧、詳細、検索 |
| AC | 外線 | 一覧、詳細、検索 |
| AD | ＦＡＸ | 詳細、検索 |
| AE | 備考 | 詳細、検索 |

**局、部、課の切り分け。**

所属名称は `葵区役所地域総務課` のように区切り文字の無いつなぎ文字列で、どこが部でどこが課かは
文字列だけでは決まらない。現行版は、組織機構図から作った `orgtable.csv`（局・部・課の辞書、
215件）を使い、左から最長一致で切る。推定ではなく突合になる。

4,911件のうち4,876名（99.3%）が機構図どおりに分かれた。残る35名は機構図に無い枝
（分館の図書館9つと市立高校2つ、計11所属）で、ひとつ前の版と同じ推定に落ちる。
表に無かった所属は実行のたびに画面に出るので、翌年 csv に足せる。

csv が無くても止まらない。無ければ推定で動き、その旨を実行時に知らせる。

**orgtable.csv の作り方。**

市が毎年出す組織機構図のPDFから機械で起こす。手で215行を打つものではない。
作るのは私用PCだけで、庁内へ持っていくのは出来上がった csv だけ。

```
python tools\make-orgtable.py tools\soshikikikouzur8.pdf orgtable.csv
```

PyMuPDF が要る（`pip install pymupdf`）。庁内では Python が使えないので、ここだけ私用PCでやる。
逆に言えば、庁内側は PowerShell だけで完結する。csv さえ持ち込めばよい。

スクリプトは、PDFの中の文字を1つずつ見て、字の大きさ、書体、位置から階層を決めている。
令和8年度版で確かめた規則は次のとおり。

| 見ているもの | 判断 |
|---|---|
| y座標が 421 の行に並ぶ | 局・区。**名前が長い局は字が小さいので、大きさでは判別できない**。位置で見る |
| ゴシック体、字の大きさ 24.0 | 部 |
| ゴシック体、それより小さい | 課・室 |
| 明朝体 | 係。**捨てる**（係は職員録の「係情報」列から取るので、この表には要らない） |
| 大きさ 48、および 25.9 | 表題と右下の凡例。組織名ではないので捨てる |
| 「（こども家庭センター）」のように括弧で始まる | 注記なので捨てる |
| 「市長」「副市長」 | 組織名ではないので捨てる |

同じ名前が複数の階層で出てきたときは、上位を採る（局 > 部 > 課）。

出来上がる csv は `名前,階層` の2列だけ。UTF-8 BOM 付き、改行 CRLF。
令和8年度版で215件（局19、部29、課167）。長い名前から順に並べてあるが、
突合するときも長い順に照合するので、並び順は気にしなくてよい。

**この csv は手で直せる。** 機構図の見立てが実態と合わないときは、csv を書き替えれば画面が
変わる。スクリプトは触らなくてよい。

- 機構図に無い組織を足したい … 行を足す（例 `御幸町図書館,課`）
- 部として扱われている室を課にしたい … その行の階層を `課` に変える

年度が変わって出来上がりがおかしいときは、上の表の前提を疑う。とくに y=421 は
その年のレイアウトに依存する。件数が極端に減った、局が0件になった、係まで拾って
しまった、といった形で出る。実行すると件数と内訳が表示されるので、そこで気づける。

**1件の形。**

```js
{
  id:1, name:"大塚　豊", kana:"オオツカ　ユタカ",
  bureau:"危機管理局",       // 局・区。シート名から
  div:"",                     // 部。組織機構表から
  dept:"危機管理課",          // 課・室
  sect:"総務係",              // 係
  org:"危機管理局危機管理課",  // 所属名称の元の表記
  title:"係長", jtype:"一般事務",
  ext:"81-4711", tel:"054-221-1012", fax:"054-251-5783",
  kenmu:[{b:"危機管理局総務課", t:"係長"}],
  note:"期間応援職員"
}
```

値が空の項目は書き出さない。1.5MB の HTML なので、空文字を4,911件ぶん並べない。

**出力。**

`職員録.html` の1ファイル。CSS も JavaScript もデータも全部その中に入る。
UTF-8 BOM 付き、改行 CRLF、1.48MB（4,911件で実測）。

備考は自由記述なので、`<` `>` `&` `'` を `\uXXXX` に逃がしてから埋め込む。
`</script>` が1つ紛れると、そこでスクリプトが終わって名簿が真っ白になり、しかもエラーが
出ないため気づけない。ダミーに無くても塞いである。

## 8. 作り

**生成の流れ。**

```
tools\viewer.html  ─ make-package.ps1 ─▶  update.ps1 の中に Base64 で埋め込み
                                              │
001_R08_shokuinroku.xlsx ─┐                   │
orgtable.csv            ─┴─ update.bat ─▶ update.ps1 ─▶ 職員録.html
```

中間ファイルは作らない。以前は `staff.js` を挟んでいたが、「どっちが最新か」が起きるので
やめた。xlsx から HTML まで1本で出す。

画面を直すときは `tools\viewer.html` を編集して `update.ps1 -Dev` で試し、固まったら
`make-package.ps1` で埋め込み直す。どちらのテンプレートを使ったかは実行時に必ず表示される。

**読み込み。**

Excel COM 版と、xlsx 直読み版の2つを持っている。

COM 版は `UsedRange` を `Value2` で範囲まるごと1回に取る。升をひとつずつ読んでいた頃は
4〜5分かかっていたのが、40秒弱になった。掴んだ COM オブジェクトは1つずつ解放する。
残骸があると次の実行が固まる。

直読み版（`-NoExcel`）は xlsx の実体が ZIP であることを使い、`xl/sharedStrings.xml` と
`xl/worksheets/sheet*.xml` を直接読む。Excel の入っていない端末でも動く。画面を直しながら
試すときはこちらのほうが速い。

**配布。**

```
[私用PC]  update.bat.txt / update.ps1.txt / orgtable.csv を ZIP
              │  拡張子を .txt にする。中身はテキストだけ
              ▼  無害化ゲートウェイ
[庁内PC]  .txt を外し、庁内の職員録 xlsx と同じフォルダへ置く
          → update.bat → 職員録.html がここで初めて生まれる
```

HTML を転送ルートに乗せると無害化が `<script>` を削除して壊れる。だから HTML は送らない。
テンプレートを Base64 で ps1 に埋め込み、庁内側で初めて組み立てる。HTML は無害化を一度も
通らない。xlsx も転送しない（「職場PCで使うときに守ること」）。

## 9. 置き場所

いまの作業場所は個人の作業用フォルダ（パスは省略）。
個人の作業用フォルダなので、本番は恒久的な共有場所へ移す必要がある。未決。

置き場所を決めるときは、アクセス権が職員に限られていること、外部公開領域と地続きでないこと、
古い版が残らない運用にできることを条件にする。

## 10. 確認できていること

- 私用PC、ダミーデータ4,911件 … 生成37秒、1.48MB、EXCEL.EXE の残留なし、検索は体感で即時
- 私用PC、Edge の `file://` … 表示、検索、チップ、列の選択の保存まで動作
- 組織機構表215件との突合 … 4,876名（99.3%）が機構図どおり、35名が表に無い11所属

庁内での確認はこれから。「ダミーで確かめられること」に挙げた外字と備考の自由記述は、
庁内で本番の職員録に対して初めて動かすときに確かめる。`タスク.md` の先頭に置いてある。
